# EDU-SRC 提分技巧与实战案例

## 一、评分标准与提分策略

### 1.1 主流 EDU SRC 平台

- **补天平台（Butian/EDU SRC）** — 国内最大的教育行业漏洞响应平台
- **漏洞盒子（VulBox/EDU SRC）** — 教育行业专项漏洞收录
- **各大高校自建ASRC** — 清华、浙大等高校自建应急响应中心
- **教育行业攻防演练** — 省级/国家级教育行业红蓝对抗

### 1.2 通用评分标准

| 严重等级 | 分数范围 | 典型漏洞类型 | 评分关键因素 |
|---------|---------|-------------|-------------|
| **严重** | 200+ | RCE、核心权限提升、批量数据泄露、核心数据库操作 | 直接影响核心业务数据（成绩、学籍、财务） |
| **高危** | 100-200 | SQL注入、垂直越权、SSRF内网探测、文件上传Getshell | 可直接获取敏感数据或服务器权限 |
| **中危** | 60-100 | 水平越权、逻辑绕过、敏感信息泄露、CSRF | 影响数据完整性和师生隐私 |
| **低危** | 20-40 | 反射型XSS、弱口令（非核心）、目录遍历 | 影响范围有限，可作为利用链起点 |

### 1.3 核心提分技巧

#### A. 资产分类决定分数倍率
- **核心资产**：教务系统、学工系统、财务系统、统一认证平台 — 同漏洞分数 x1.5~2
- **边缘资产**：校园论坛、就业网、校友会 — 同漏洞分数 x0.5~0.8
- **策略**：瞄准核心资产，即使是弱口令也能拿中危

#### B. 漏洞链组合法（最关键提分技巧）
- 单个低危（如信息泄露）只有 20-40 分
- **组合链**：信息泄露 + 弱凭证 + 数据库泄露 = 中危/高危（60-150分）
- 平台明确奖励"漏洞链"组合提交
- **典型链**：信息收集 -> 弱口令 -> 越权 -> 批量数据获取

#### C. 报告质量加分
- 附带清晰 PoC、影响证据截图（脱敏数据）、修复建议 — 可升一级（中危->高危）
- 强调**业务影响**比纯技术描述分数更高
  - 坏："发现SQL注入漏洞"
  - 好："该SQL注入可查询全校学生身份证号、家庭住址、考试成绩，影响XX万条记录"

#### D. 专项活动双倍积分
- 平台定期举办"教育行业专场"活动，期间教育行业漏洞双倍积分
- 关注补天、漏洞盒子的活动通知

#### E. 资产拓展技巧
- 使用 FOFA/Shodan/360Quake 针对性搜索教育网资产：
  - `body="edu.cn" && body="管理"`
  - `cert=".edu.cn"`
  - `org="China Education and Research Network Center"`
- 老旧子域名（Struts2、过时Tomcat、Shiro硬编码密钥）在edu域中大量存在，容易出高危

### 1.4 各漏洞类型参考分数

| 漏洞类型 | 基础分 | 核心资产倍率后 | 备注 |
|---------|-------|--------------|------|
| Shiro RCE（默认key） | 100-150 | 150-200 | edu领域最常见的高危之一 |
| SQL注入（核心库） | 80-120 | 120-180 | 需确认能查出敏感字段 |
| 垂直越权（学生->管理员） | 60-100 | 100-150 | 评分最高的逻辑漏洞类型 |
| 任意用户登录/密码重置 | 60-100 | 80-120 | 统一认证系统的重灾区 |
| 文件上传Getshell | 80-120 | 120-160 | 课件/头像/主题上传点 |
| SSRF->内网 | 60-80 | 80-120 | 配合内网脆弱系统打分更高 |
| 批量信息泄露（IDOR） | 40-80 | 80-120 | 证书下载/成绩查询接口 |
| JWT alg:none/弱密钥 | 40-60 | 60-100 | 智慧校园App后台接口 |
| 水平越权 | 30-60 | 60-80 | 遍历学号/用户ID |
| 反射型XSS | 10-20 | 20-40 | 配合社工钓鱼使用 |
| 弱口令（非核心） | 10-20 | 20-40 | 需确认能进入后台 |

## 二、实战案例汇总

### 案例1：从信息收集到Getshell的完整攻击链

**来源**：先知社区 / 奇安信攻防社区
**漏洞类型**：信息收集 -> 弱口令 -> 文件上传绕过 -> Getshell
**目标**：某高校综合管理平台

**发现过程**：
1. **信息收集**：使用 OneForAll 子域名扫描，发现多个老旧子域名
2. **后台发现**：通过目录扫描找到 `/admin` 登录入口
3. **弱口令**：`admin/admin123` 直接登录后台
4. **文件上传绕过**：在课件上传功能中，前端限制仅允许上传图片类型，BurpSuite抓包修改 Content-Type 为 `image/png`，实际文件为 JSP Webshell
5. **Getshell**：上传成功，访问 Webshell 路径，执行系统命令

**利用方式**：`Content-Type` 绕过 + 双扩展名绕过（`.jpg.jsp`）
**影响**：获取服务器权限，可进一步内网渗透
**修复建议**：后端校验文件内容头（Magic Number），禁用可执行脚本目录的执行权限

### 案例2：统一身份认证（CAS）登录绕过

**来源**：安全客
**漏洞类型**：SSO/CAS Ticket伪造 -> 任意用户登录
**目标**：某985高校CAS统一认证系统

**发现过程**：
1. 抓取 CAS 登录流程，分析 Service Ticket 生成逻辑
2. 发现 Service Ticket 未与应用回调地址绑定
3. 构造特殊 `service` 参数绕过 Ticket 校验
4. 以管理员身份登录所有子应用

**利用方式**：Ticket 复用 + service 参数篡改
**影响**：攻击者可登录任意用户的账号，包括管理员
**修复建议**：严格校验 Service Ticket 与回调地址的白名单绑定，使用 HTTPS 并设置 Secure/HttpOnly Cookie

### 案例3：正方教务系统SQL注入

**来源**：补天平台公开漏洞 / 跳跳糖
**漏洞类型**：SQL注入 -> 管理员权限获取
**目标**：使用正方教务系统的高校

**发现过程**：
1. 识别目标使用正方教务系统（通过页面特征、URL路径）
2. 在成绩查询接口中发现参数未过滤
3. SQLMap跑出数据库，发现管理员表
4. 破解管理员密码哈希，进入后端管理平台

**利用方式**：`' UNION SELECT ...` 联合查询注入
**影响**：管理员权限，可查看/修改全校成绩、学籍信息
**修复建议**：使用参数化查询，避免拼接SQL语句

---

### 案例4：Shiro RememberMe 反序列化 RCE

**来源**：Seebug Paper / 补天平台
**漏洞类型**：Shiro RCE（反序列化命令执行）
**目标**：某教育局网站（Shiro框架）

**发现过程**：
1. **指纹识别**：响应头中包含 `rememberMe=deleteMe` 标识
2. **密钥检测**：使用 Shiro-Exploit 工具检测默认密钥 `kPH+bIxk5D2deZiIxcaaaA==`
3. **漏洞利用**：使用 ysoserial 生成 CommonsCollections 链 payload
4. **命令执行**：通过 `ping` 或 DNSLog 验证命令执行成功
5. **权限获取**：执行反弹 shell 命令，获取服务器权限

**利用工具**：ShiroExploit、ysoserial
**影响**：服务器被完全控制，可内网横向移动
**修复建议**：升级 Shiro 至 1.10.0+，替换硬编码密钥，禁用 RememberMe（如非必要）

---

### 案例5：学生证书下载接口 IDOR 批量泄露

**来源**：教育行业SRC漏洞库
**漏洞类型**：IDOR（未授权访问）-> 学生信息批量泄露
**目标**：高校电子证书下载系统

**发现过程**：
1. 定位高校网站"证书下载"功能（四六级成绩单、学位证电子版）
2. 抓包发现下载链接格式：`https://univ.edu.cn/download?cert_id=20230001`
3. 修改 cert_id 参数遍历：`20230001` -> `20239999`
4. 后端未校验当前会话与学号的从属关系
5. 批量下载成功，获取全校学生信息（姓名、身份证号、照片、成绩）

**利用方式**：参数遍历（BurpSuite Intruder 批量发包）
**影响**：数万至数十万学生敏感信息泄露（姓名、身份证号、学籍信息、照片）
**修复建议**：后端严格执行当前 Session 的用户身份与请求参数的绑定校验；下载链接加入随机 Token

### 案例6：JWT 算法混淆致身份伪造

**来源**：教育行业众测报告
**漏洞类型**：JWT alg:none 攻击 / 弱密钥爆破 -> 任意用户登录
**目标**：某高校智慧校园 App 后台 API

**发现过程**：
1. 抓取 API 请求发现使用 JWT Token：`Authorization: Bearer eyJxxx...`
2. 解码 JWT Header：`{"alg":"HS256","typ":"JWT"}`
3. 尝试 `alg: none` 攻击：修改 Header 为 `{"alg":"none"}`，Payload 中设置 `role=admin`
4. 后端未校验算法类型，直接信任伪造 Token
5. 以管理员身份调用所有后台 API

**利用方式**：修改 JWT Header alg -> none，伪造 Payload
**影响**：攻击者可以任意用户/管理员身份调用 API 接口
**修复建议**：禁用 none 算法，严格校验算法白名单，使用 RS256 非对称加密，缩短 Token 有效期

---

### 案例7：教育云平台 SSRF 内网探测

**来源**：CNVD技术合集
**漏洞类型**：SSRF -> 内网资产探测
**目标**：某省教育云平台

**发现过程**：
1. 云平台的"网站截图"功能存在 URL 参数：`/screenshot?url=xxx`
2. 修改 url 参数为内网地址：`http://10.0.0.1:8080`
3. 返回截图确认 SSRF 漏洞存在
4. 进一步探测内网存活主机和脆弱服务（如未授权 Redis、MySQL）
5. 利用内网 Redis 未授权访问写入 SSH 公钥

**利用方式**：SSRF -> 内网扫描 -> Redis 未授权访问
**影响**：内网全部资产暴露，可横向移动到核心数据库
**修复建议**：限制 URL 请求的目标 IP（禁止内网地址段），使用白名单/正则过滤

### 案例8：选课系统并发逻辑漏洞（条件竞争）

**来源**：安全客
**漏洞类型**：Race Condition -> 重复选课 / 选课绕过限制
**目标**：高校教务选课系统

**发现过程**：
1. 选课系统限制每人只能选 2 门选修课
2. BurpSuite 抓取选课请求，发送到 Intruder
3. 使用 Pitchfork/Parallel 模式同时发送多个选课请求
4. 后端未加锁，并发请求导致同一时间多条记录写入
5. 成功选上 5 门课（突破了 2 门上限）

**利用方式**：并发请求绕过限制校验
**影响**：可突破选课限制、重复退补选、抢课
**修复建议**：后端使用数据库事务+行锁，对关键操作加入分布式锁或乐观锁

---

### 案例9：弱口令 + 密码重置绕过

**来源**：补天平台漏洞库
**漏洞类型**：弱口令 + Token可预测 -> 任意用户密码重置
**目标**：高校统一身份认证系统

**发现过程**：
1. 发现密码重置功能发送 Token 到邮箱
2. 分析 Token 生成算法：`md5(时间戳 + 用户ID)`
3. Token 无过期时间限制、无尝试次数限制
4. 批量生成 Token 脚本，遍历重置学生账号密码
5. 登录后获取学生个人信息

**利用方式**：Token 可预测 + 批量遍历
**影响**：任意用户密码可被重置，核心隐私泄露
**修复建议**：Token 使用 CSPRNG（安全伪随机数生成器）生成，加入过期时间，限制尝试次数

### 案例10：教育系统供应商通用 RCE（供应链攻击）

**来源**：CNVD / 嘶吼RoarTalk
**漏洞类型**：通用系统 RCE -> 批量利用
**目标**：金智/青果/正方教务系统、蓝凌OA、XXL-JOB、通达OA、致远OA、用友NC

**发现过程**：
1. 识别教育行业通用 CMS 框架
2. 查询 CNVD/Seebug 中对应系统的已知漏洞
3. 在课表查询、文件打印、通知发布等功能中发现未过滤的命令拼接
4. 构造 Payload 执行系统命令

**受影响系统清单**：
- 正方教务系统
- 青果教务系统
- 强智教务系统
- 金智教育系列
- 蓝凌OA（教育版）
- 通达OA（教育版）
- 致远OA（教育版）
- 用友NC（教育版）
- XXL-JOB 调度中心

**利用方式**：命令注入 / 反序列化
**影响**：同一套系统在多个高校中均存在漏洞，批量化利用影响面巨大
**修复建议**：及时更新供应商补丁，对命令执行函数参数做严格过滤

## 三、高价值漏洞模板

### 3.1 批量信息泄露（最稳定高分来源）

**靶点清单**：
- 学生证书下载（四六级/毕业证/学位证）
- 成绩查询接口
- 学籍信息接口
- 教师信息展示页面
- 统一认证 API `/api/user/info`
- 校友信息数据库

**检测思路**：
```
请求: GET /api/download/cert?studentId=20230001
响应: {name, idCard, studentId, major, photo}

遍历 studentId: 20230001 -> 20235000
验证是否可获取他人数据（IDOR）
```

**提分要点**：
- 必须有证据证明能查到**真实他人的数据**（至少3条不同用户记录）
- 截图包含批量数据条数统计
- 说明泄露字段的敏感性（身份证号、家庭住址、联系方式等）

### 3.2 权限绕过/任意用户登录（高危核心）

**靶点清单**：
- CAS/SSO 单点登录系统
- JWT Token 认证接口
- Shiro 框架应用
- 后台管理面板
- API 网关

**检测思路**：
```
1. Shiro RememberMe 检测：
   请求头: Cookie: rememberMe=任意值
   响应头: 包含 rememberMe=deleteMe -> 存在 Shiro

2. JWT alg:none 检测：
   原始: eyJhbGciOiJIUzI1NiJ9...
   修改: eyJhbGciOiJub25lIn0... (base64({"alg":"none"}))

3. 水平越权检测：
   POST /api/updateProfile
   修改 body 中的 userId/studentId/role 参数
```

### 3.3 RCE/命令执行（最高分来源）

**靶点清单**：
- 文件上传功能（课件/头像/附件/主题）
- 课表查询参数注入
- 文件打印/导出功能
- OA 系统接口
- 系统 Ping/Traceroute 功能

**检测思路**：
```
1. 文件上传测试：
   上传 test.jpg.jsp -> 双扩展名绕过
   上传 test.jsp -> Content-Type: image/png
   上传 .htaccess -> 配置文件上传

2. 命令注入检测：
   /ping?host=127.0.0.1;id
   /export?type=pdf&file=test;whoami
   
3. Shiro RCE（默认key）：
   kPH+bIxk5D2deZiIxcaaaA==
   使用 ShiroExploit 工具检测
```

### 3.4 教育行业通用系统漏洞清单

| 系统名称 | 常见漏洞 | 利用难度 | 得分潜力 |
|---------|---------|---------|---------|
| 正方教务系统 | SQL注入、越权、XSS | 低-中 | 高危 |
| 青果教务系统 | SQL注入、文件上传 | 低-中 | 高危 |
| 强智教务系统 | 逻辑漏洞、越权 | 中 | 中高危 |
| 金智教育系列 | SSRF、RCE | 中 | 高危 |
| 蓝凌OA | 反序列化RCE | 低（有公开POC） | 严重 |
| 通达OA | 文件上传、SQL注入 | 低（有公开POC） | 严重 |
| 致远OA | 反序列化、文件泄露 | 低（有公开POC） | 严重 |
| 用友NC | RCE、反序列化 | 中 | 严重 |
| XXL-JOB | 未授权访问 -> RCE | 低 | 高危 |
| Apache Shiro | 反序列化RCE | 低（默认key） | 高危 |

### 3.5 典型利用链模板

**链A：通用系统链（最稳定）**
```
扫描教育网资产
  -> 识别通用系统指纹（正方/青果/通达OA等）
    -> 查询 CNVD 对应系统漏洞
      -> 利用公开 PoC 直接获取权限
```

**链B：Shiro链（edu领域最常见）**
```
子域名收集
  -> 逐个检测 Shiro 框架（响应头有 rememberMe=deleteMe）
    -> 检测默认密钥（kPH+bIxk5D2deZiIxcaaaA==）
      -> ysoserial 生成 payload
        -> 命令执行 -> 反弹 shell
```

**链C：逻辑链（最高效）**
```
寻找注册/登录功能
  -> 分析 API 请求中的 Token/JWT/Cookie
    -> 尝试 JWT alg:none / 弱密钥爆破
      -> Token 伪造 -> 管理员权限
        -> 批量导出数据
```

**链D：上传链（最直接）**
```
寻找文件上传点（头像/课件/附件）
  -> BurpSuite 抓包修改
    -> Content-Type 绕过
    -> 双扩展名绕过
    -> .htaccess 绕过
      -> Webshell -> 命令执行
```

**链E：信息泄露链（最易出）**
```
找到批量查询接口（成绩/证书/缴费）
  -> 检查参数是否为数字/递增
    -> BurpSuite Intruder 参数遍历
      -> 确认可查询他人数据
        -> 截图证据 + 统计泄露条数
```

## 四、报告撰写技巧

### 4.1 高分报告模板

```markdown
## 漏洞标题：[严重/高危/中危] [系统名称] [漏洞类型] 导致 [业务影响]

## 漏洞描述
（简要描述漏洞原理和影响范围）

## 影响范围
```

## 六、EDU-SRC 实战总结

### 核心结论

1. **教育行业是最容易出漏洞的行业之一** — 系统老旧、版本滞后、通用系统多、供应链复杂
2. **逻辑漏洞是edu领域最高效的提分路径** — 不需要0day，不需要复杂工具，分析业务逻辑即可
3. **通用系统漏洞可批量化** — 一个教务系统的通用漏洞可在几十所高校复现
4. **Shiro + 弱口令 + IDOR = edu三大神器** — 覆盖80%以上的edu高危漏洞
5. **组合链比单漏洞分数高50-100%** — 把多个低危组合成一条攻击链提交
6. **核心资产决定分数上限** — 瞄准教务/学工/财务/统一认证四大核心系统
7. **报告质量直接影响评级** — 清晰完整、有业务影响说明的报告可提级

### 攻击路径优先级

```
第一优先：抓通用系统（正方/青果/通达OA/Shiro）
  -> PoC现成、批量化、稳定出高危

第二优先：找核心系统的逻辑漏洞（教务/学工/财务）
  -> IDOR/越权/JWT绕过 -> 批量数据泄露 = 稳定中高危

第三优先：找文件上传/RCE
  -> 可能出严重漏洞，但需要更多技巧

第四优先：SQL注入
  -> 教育网过滤较弱，但需要确认数据价值
```
