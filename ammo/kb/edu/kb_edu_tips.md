## 一、核心知识速查表

| 主题 | 要点 | 示例 | 适用场景 |
|------|------|------|----------|
| **EDU-SRC收录范围** | 教育部、各省教育厅/教委、各级教育局、学校（含小学/初中/高中）、教育相关软件 | 高校统一身份认证系统、教务系统、选课系统、就业系统、实验室管理系统 | 确认攻击目标是否在收录范围内 |
| **高Rank漏洞类型** | RCE（远程命令执行）、SQL注入获取数据、批量越权泄露敏感信息、文件上传GetShell | GitLab CVE-2021-22205反弹Shell直接12Rank | 冲击高分排行榜 |
| **中等Rank漏洞类型** | 弱口令登录后台、未授权访问、逻辑缺陷绕过、信息泄露（学号/身份证） | 后台admin:admin登录，漏洞评分中危 | 日常稳定上分 |
| **低Rank漏洞类型** | 反射型XSS、低危信息泄露、简单目录遍历 | 前端参数修改绕过、小范围信息泄露 | 填补漏洞数量 |
| **EDU加分项** | 涉及学生身份证/学号批量泄露、可进内网、涉及财务系统 | 6000+教师身份证信息泄露→高危 | 证明危害性提升评分 |
| **证书获取条件** | 通常需提交N个高危/中危漏洞，不同平台规则不同 | EduSrc平台累计Rank达标可申请证书 | 求职简历加分 |
| **EDU-SRC vs 普通SRC** | 教育系统安全意识较差、漏洞密度高、系统老旧、证书认可度高 | 高职院校弱口令比例远高于企业SRC | 新手首选入门 |

## 二、EDU-SRC评分标准详解

### 2.1 评分因素维度

| 维度 | 说明 | 提分技巧 |
|------|------|----------|
| **危害程度** | 能造成的数据泄露范围、系统控制程度 | 尽量证明可以批量获取数据，而非单条 |
| **影响范围** | 影响多少用户、涉及多少系统 | 扩大测试面，展示数据量（如"可遍历6000+教师信息"） |
| **利用难度** | 是否需要特殊条件才能利用 | 强调无需特殊权限即可利用 |
| **资产重要性** | 核心业务系统 vs 边缘系统 | 优先打统一身份认证、教务系统、学工系统 |
| **证明完整性** | 是否提供完整POC、复现步骤 | 详细录屏+步骤说明+修复建议 |

### 2.2 常见漏洞评分参考

| 漏洞类型 | 典型评分 | 关键提分点 |
|----------|----------|------------|
| SQL注入（DBA权限） | 高危/高分 | 证明可读取所有数据库、获取系统权限 |
| RCE/GetShell | 高危/12Rank+ | 证明可执行命令、控制服务器 |
| 批量越权（IDOR） | 高危/高分 | 证明可批量遍历所有用户数据 |
| 逻辑漏洞（支付/重置密码） | 中-高危 | 证明可造成实际资金损失或账号盗用 |
| 弱口令 | 中危 | 证明弱口令可登录后台+后台功能危害 |
| 未授权访问 | 中危 | 证明未授权可访问的数据/功能敏感 |
| XSS（存储型） | 中危 | 证明可获取管理员Cookie/操作后台 |
| XSS（反射型） | 低危 | 一般评分最低 |

### 3.2 教育资产收集核心技巧

**FOFA/鹰图搜索语法：**
```
domain="edu.cn"                     # 搜索edu.cn结尾资产
ip.isp="教育"                        # 搜索教育网段（规模更大）
body="统一身份认证" && domain="edu.cn"  # 精准搜索身份认证系统
icon_hash="xxxx"                     # 搜索特定图标（如GitLab）
```

**Google Hacking语法（EDU专项）：**
```
site:edu.cn intext:管理|后台|登陆|用户名|密码|系统|admin|login
site:edu.cn inurl:login|admin|manage|system
site:edu.cn intext:"学号"
site:edu.cn intext:"身份证"

site:edu.cn intitle:管理后台

```

**信息收集流程：**
1. 鹰图/FOFA搜 `domain="edu.cn"` → 获取目标学校资产
2. OneForAll/Subfinder跑子域名
3. JSFinder/Packer-Fuzzer分析JS接口
4. 企查查/小蓝本查询知识产权信息
5. ICP备案反查获取更多域名
6. intelx.io 邮箱信息收集
7. 微信小程序/公众号联动收集

## 四、实战案例库

### 案例1：首次EDU-SRC三连挖（弱口令+未授权+文件上传）

**来源：** CSDN 作者：Sugobet
**目标：** 某学院管理系统
**漏洞链：**
1. **弱口令登录后台**：发现二级学院公众号链接暴露IP:端口，去掉端口走80端口直接进入后台管理登录页，尝试admin:admin成功登录 → **中危**
2. **未授权访问**：后台所有接口无权限校验，Token形同虚设，直接遍历获取所有学生/教师账号信息（明文） → **中危**
3. **任意文件上传**：后台存在文件上传点，仅前端JS校验，删除前端限制或直接Burp发包绕过 → **低危**

**关键思路：**
- 公众号/小程序常暴露内部系统，且安全防护弱
- 内网系统映射到公网时，端口映射规则可能有逻辑漏洞
- 弱口令字典：admin:admin, admin:123456, admin:888888

---

### 案例2：IDOR导致6000+教师身份证信息泄露

**来源：** 腾讯云开发者社区 作者：亿人安全
**目标：** 某某学院一站式服务大厅
**漏洞链：**
1. 登录一站式服务大厅后观察API调用
2. 发现 `getUserInfo?userid=xxxx` 接口返回身份证号
3. 修改userid参数可遍历获取任意用户信息 → **IDOR越权**
4. 在选课页面发现6000+教师工号列表
5. 工号+IDOR接口 → 批量获取6000+教师完整身份证信息

**关键思路：**
- 前后端分离架构下，API接口常缺乏权限校验
- 信息收集与漏洞利用要结合，工号=IDOR遍历字典
- 证明批量危害性比单条泄露评分高很多

---

### 案例3：统一身份认证逻辑绕过

**来源：** CN-SEC 作者：不秃头的安全
**目标：** 某大学统一身份认证系统
**漏洞链：**
1. 通过FOFA/鹰图找到统一身份认证入口
2. 通过信息收集（弱口令+导出功能）获取学号列表
3. 忘记密码功能中，抓取返回包发现 `flag:false` → 改为 `true`
4. 成功绕过手机验证码，重置任意账号密码

**关键技巧：**
- 找回密码/忘记密码功能是逻辑漏洞高发区
- 关注返回包中的布尔值（false/true）、状态码、msg字段
- Java开发的统一认证系统常见此类前端校验可绕过

---

### 案例4：高校就业系统SQL注入

**来源：** 腾讯云开发者社区 作者：亿人安全
**目标：** 某大学学生就业综合管理服务平台
**漏洞链：**
1. 登录就业系统个人中心
2. 在就业数据统计模块发现功能异常
3. Burp抓包分析POST请求参数
4. sqlmap一把梭获取Oracle数据库交互式SQL shell
5. 可查询所有数据库用户和数据

**关键思路：**
- 统计/报表功能是SQL注入重灾区（动态拼接SQL）
- 就业系统常被忽略，安全防护薄弱
- Oracle数据库提权路径丰富

---

### 案例5：Nday批量收割

**来源：** 博客园 作者：Mr-Ryan
**思路：** 利用Nday漏洞批量检测教育资产
**具体操作：**
1. GitLab CVE-2021-22205：鹰图搜索GitLab图标+edu域名，导出数据批量检测
2. SpringBoot未授权访问：搜索Java白页特征，批量检测actuator等端点
3. ThinkPHP RCE：搜索ThinkPHP路由特征，批量检测5.x RCE

**关键思路：**
- 教育行业资产量大，Nday批量检测效率极高
- 关注GitLab、SpringBoot、ThinkPHP等高校常见组件
- 一个Nday在教育网内能扫出多个漏洞

## 五、提分组合拳与利用链

### 5.1 经典提权组合链

```
信息收集 → 弱口令进后台 → 后台存在文件上传 → GetShell → 内网渗透
信息收集 → 找学号/工号 → 统一认证绕过 → 进教务系统 → 批量数据
Nday检测(GitLab/ThinkPHP) → RCE → 服务器权限 → 数据导出
API接口分析 → 发现IDOR → 批量用户数据 → 证明危害性
```

### 5.2 串联组合提分技巧

| 单漏洞 | 组合后 | 评分提升 |
|--------|--------|----------|
| 弱口令(中危) | 弱口令进后台+后台信息泄露+文件上传 | 可提升为"连锁漏洞"评分更高 |
| XSS(低危) | XSS打到管理Cookie+后台操作+数据导出 | 组合后可评中高危 |
| SQL注入(中危) | SQL注入+DBA权限+读取全部数据 | 高危起步 |
| IDOR(中危) | IDOR+批量遍历+批量数据导出 | 高危 |

### 5.3 教育系统通杀思路

1. **统一身份认证绕过**：Java CAS系统普遍存在返回包false改true
2. **OneAuth/UCenter绕过**：返回包参数修改可绕过
3. **微信小程序入口**：小程序绑定校内账号，API接口常无鉴权
4. **旧版API未下线**：教育系统升级后旧版本API常未下线且无鉴权
5. **默认密码**：学号/工号+默认密码（123456/身份证后六位/生日）
6. **C段扫描**：学校C段内网服务常暴露到公网

## 六、报告撰写技巧

### 6.1 报告结构模板

```
1. 漏洞标题：[EDU-平台名] 系统名称 + 漏洞类型 + 危害等级
   例：[EDU-某大学] 一站式服务大厅API接口IDOR越权致6000+教师身份证泄露

2. 漏洞详情
   - 漏洞描述：清晰描述漏洞原理
   - 影响范围：哪些系统/多少用户受影响
   - 风险分析：可能造成的实际危害

3. 复现步骤（分步写明，附带截图）
   Step 1: 登录系统，访问xxx页面
   Step 2: 开启Burp拦截，观察到API接口xxx
   Step 3: 修改参数xxx为任意值
   Step 4: 响应返回其他用户敏感数据

4. 漏洞证明
   - POC请求/响应内容（文字版）
   - 关键截图（含时间戳+系统URL）

5. 修复建议（分条列出，具体可操作）
```

### 6.2 报告提分技巧

| 技巧 | 说明 |
|------|------|
| **标题要抓人眼球** | 包含危害性关键词："批量泄露""任意账户""GetShell" |
| **数据量化** | "可遍历6000+条""可获取全校10万学生信息"比模糊描述分高 |
| **录屏证明** | 高危漏洞附GIF/视频录屏，证明可操作性 |
| **修复建议要专业** | 给出具体修复代码/方案，而非泛泛而谈 |
| **强调无需特殊条件** | "无需登录""普通用户权限即可""无需交互"都是加分项 |
| **突出业务影响** | "涉及学生毕业""影响教学管理""涉及财务系统" |

### 6.3 常见扣分项避免

- 缺少详细复现步骤
- 截图不清晰/无URL时间戳
- 危害性描述模糊
- 修复建议过于笼统（如"加强安全意识"）
- 未区分测试数据与真实数据
- 报告中包含真实敏感数据（应打码）

## 七、危害性证明思路

| 漏洞类型 | 危害证明方法 |
|----------|-------------|
| SQL注入 | 用sqlmap --os-shell获取交互式shell截图，证明可执行系统命令 |
| RCE | 执行whoami/ipconfig/pwd命令，截图证明服务器权限 |
| IDOR | 遍历3个以上不同用户ID，证明可获取任意用户数据 |
| 弱口令 | 登录后台后展示后台可操作的功能/数据范围 |
| 逻辑缺陷 | 演示完整攻击链：从无权限到获取敏感数据 |
| 信息泄露 | 证明泄露数据可被用于进一步攻击（如身份证+学号=身份盗用） |

## 九、教育行业渗透测试合规边界

| 可测范围 | 不可测范围 |
|----------|------------|
| 学校对外发布的Web系统 | 非授权的内网渗透（需授权） |
| 各级教育单位官网 | 核心数据库直接攻击（尤其涉及学生档案） |
| 教育类APP/小程序 | 社会工程学攻击教师/学生个人 |
| 教务/学工等管理系统 | 破坏性测试（DDoS、数据篡改） |
| 教育邮箱（Web端） | 修改/删除生产数据 |
| 统一身份认证系统 | 超出测试范围的横向移动 |

**合规要点：**
- 所有测试需在EDU-SRC平台规则允许范围内
- 发现漏洞后仅截图作为证明，**不得下载/保存真实敏感数据**
- 测试后及时清理测试数据
- 不得公开未修复的漏洞细节（遵循负责任的披露原则）
- 涉及身份证等个人敏感信息，打码处理后再上传报告

## 十、通用修复建议模板

### 10.1 各类漏洞通用修复方案

**弱口令：**
- 实施强密码策略（8位以上，含大小写+数字+特殊字符）
- 禁止常见弱口令字典中的密码
- 首次登录强制修改密码
- 开启多因素认证

**SQL注入：**
- 使用参数化查询（PreparedStatement）
- 严格过滤用户输入的特殊字符
- 最小化数据库用户权限
- 部署WAF并配置SQL注入规则

**IDOR/越权：**
- 服务端校验当前用户对目标资源的访问权限
- 使用随机/加密的ID而非自增数字
- 实施统一权限认证网关
- 敏感接口增加二次校验

**文件上传：**
- 白名单校验文件类型（而非黑名单）
- 文件存储与Web根目录分离
- 重命名上传文件为随机字符串
- 限制上传文件大小

### 10.2 给厂商的修复建议书写要点

1. **按优先级排序**：高危>中危>低危
2. **具体可操作**：不要只写"加强安全"，要写"在UserController.java第XX行增加权限校验代码"
3. **参考标准**：引用OWASP等国际安全标准
4. **临时+长期方案**：先给出临时缓解措施，再给出长期修复方案
5. **测试验证**：给出修复后的验证方法

## 十一、EDU-SRC挖洞经验总结

### 11.1 难度分级

```
证书大学站 > 资产多的普通大学 > 资产多的职业学院 > 有账号密码进内网
```

### 11.2 高频漏洞Top 10

1. 弱口令登录后台（EDU最常见）
2. IDOR越权（任意用户信息查看/修改）
3. SQL注入（统计/搜索/导出功能）
4. 逻辑缺陷（密码重置/登录绕过）
5. 未授权访问（API接口无鉴权）
6. 信息泄露（学号/身份证/Git信息）
7. 文件上传绕过
8. XSS存储型
9. SSRF
10. Nday漏洞（GitLab/SpringBoot/ThinkPHP）

### 11.3 一句话核心经验

> **信息收集决定上限，漏洞利用决定下限。**  
> **收集到别人收集不到的资产，就能挖到别人挖不到的洞。**  
> **弱口令yyds！**  
> **关注微信公众号/小程序，这里的系统通常安全最弱。**  
> **Nday批量检测在edu网段效率极高。**  
> **信息收集+漏洞利用组合，威力远超单个漏洞。**
