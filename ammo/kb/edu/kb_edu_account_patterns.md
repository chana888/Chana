## 一、学号规律与收集

### 1.1 学号通用编码结构

中国高校学号通常由以下字段组合而成，极具规律性：

| 字段 | 作用 | 常见格式 |
|---|---|---|
| **入学年份 (YYYY 或 YY)** | 标识入学批次 | `2023` (4位) 或 `23` (2位) |
| **学院/系代码** | 代表所属二级学院（如 01=计算机学院） | 2-3位数字 |
| **专业代码** | 代表具体专业（如 01=计算机科学与技术） | 2位数字 |
| **班级代码** | 代表行政班级序号 | 2位数字（01、02...） |
| **序号** | 班级内部顺序（按拼音/成绩/随机） | 2-3位数字 |

### 1.2 常见编码结构模型

| 结构模型 | 位数 | 字段分解 | 特点 |
|---|---|---|---|
| **经典10位模型** | 10位 | `YY`(2) + 学院(2) + 专业(2) + 班级(2) + 序号(2) | 应用最广，省属高校常见 |
| **年份开头4位模型** | 10-11位 | `YYYY`(4) + 学院(2) + 专业(2) + 班级(2) + 序号(2) | 便于按年份筛选 |
| **多校区/大学科模型** | 12位 | `YYYY`(4) + 学院(3) + 专业(3) + 班级(2) + 序号(2) | 大型综合性大学/合并院校 |
| **含学历代码模型** | 10-12位 | `G`(学历) + `YY`(2) + 学院(3) + 专业(3) + 序号(2-3) | 研究生或本硕博统一编排 |

### 1.3 额外字段

- **学历层次代码**：`1`/`U`/`B`=本科，`2`/`G`/`M`=硕士，`3`/`D`=博士
- **校区代码**：多校区大学增加校区标识位
- **招生类型代码**：普高/专升本/港澳台/留学生等
- **性别代码**：极少数高校用奇数=男、偶数=女

### 1.4 学号批量生成方法

```
已知某大学学号格式为 2023XXXXXX (10位)：
- 学院代码范围：01-30 常见
- 专业代码范围：01-20 常见
- 班级代码范围：01-10 常见
- 序号范围：01-50

=> 每个年级可生成 30×20×10×50 = 30万 个可能学号
=> 通过列表页、公示信息可缩小范围
```

### 1.5 学号收集来源

| 来源 | 说明 |
|---|---|
| **学校官网公示** | 奖学金名单、竞赛获奖、学生组织名单、宿舍分配表 |
| **教务处公开查询** | 课表查询API、成绩查询接口（部分未鉴权） |
| **图书馆系统** | 借阅排行、新书通报常显示学号 |
| **学生组织公众号** | 部门名单、活动参与名单 |
| **OA/办公系统** | 通讯录导出、组织架构 |
| **GitHub泄露** | 学生作业、项目代码硬编码学号 |
| **录取公示** | 部分高校录取名单含完整考生号→映射学号 |
| **学信网接口** | 部分爬虫接口 |


## 二、默认密码规律

### 2.1 通用默认密码生成规则

| 规则类型 | 典型密码 | 出现频率 |
|---|---|---|
| **学号即密码** | `2023123456` | 极高 |
| **身份证后6位** | `12345X` | 极高 |
| **身份证全号** | `110101200001010012` | 高 |
| **生日8位** | `20000101` | 高 |
| **生日6位** | `000101` | 中 |
| **固定短密码** | `000000` / `111111` / `123456` | 高 |
| **身份证后6位+学号** | `12345X20231234` | 中 |
| **姓名字母+数字** | `zhangsan123` | 中 |
| **学号后6位** | `123456`（学号的后6位） | 中 |
| **空密码** | （留空不填） | 老系统常见 |
| **录取通知书编号** | 见通知书 | 部分学校 |
| **考生号** | 高考考生号 | 部分学校 |

### 2.2 统一身份认证密码规律

- **初始密码**：多数高校初始密码 = 身份证后六位/后八位，或出生年月日（8位）
- **强制修改**：首次登录强制修改，但大量学生长期不改或只做简单变换
- **常见变换**：追加 `!1`、`@123`、`#`、`a`、`2024` 等后缀
- **密码提示问题**：重置密码的验证信息常为学号、姓名、辅导员电话（易通过公开渠道获取）
- **CAS系统特点**：部分CAS系统返回不同错误提示（"密码错误" vs "用户不存在"），可辅助枚举

### 2.3 教职工账号密码规律

| 身份 | 账号 | 默认密码 |
|---|---|---|
| **教师** | 工号（通常6-8位） | 工号本身 / 身份证后6位 / `000000` / `123456` |
| **辅导员** | 工号 | 同教师规则，常存在弱口令 |
| **院系管理员** | 工号或特定前缀+工号 | 同上 |
| **教务管理员** | `admin` / `教务` + 编号 | admin/manage/admin123 |

## 四、账号收集方法

### 4.1 公开信息收集

| 方法 | 详细操作 | 示例 |
|---|---|---|
| **学院官网** | 爬取师资队伍页面→教师工号/姓名 | `/szdw/` 页面列表 |
| **学生公示** | 奖学金/评优/竞赛公示含学号姓名 | 通常在 `教务处` 或 `学工处` |
| **课表查询** | 部分学校课表API不鉴权，返回选课学生学号 | `/jwglxt/kebiao` |
| **组织架构** | 学生会/社团/党支部名单 | 学校官网或公众号 |
| **宿舍分配** | 新生宿舍分配表常含学号 | 后勤处/学工处 |
| **论文列表** | 毕业论文题目公示含学号姓名 | 教务处网站 |
| **招生信息** | 录取名单/分班名单 | 招生网 |

### 4.2 API接口枚举

常见脆弱API端点（需注意是否鉴权）：

```
/jwglxt/xxx/queryStudentInfo
/api/student/getInfo
/mobile/student/search
/jwglxt/kebiao/query
/api/edu/student/list
/student/getInfoBySid
/xxcx/queryXsxx
/zhcx/queryXsjbsj
```

**典型泄露字段**：学号、姓名、身份证号、民族、生源地、联系电话、电子邮箱、家庭地址、照片

**攻击方式**：直接遍历学号（POST/GET参数 `sid`），JSON响应中常含敏感字段未脱敏

**防护缺失**：缺乏token鉴权、referer验证、速率限制或API网关保护

### 4.3 学号枚举技巧

```
1. 首先找到1-2个已知学号（通过公示等渠道）
2. 分析学号编码结构（年份/学院/专业/班级/序号）
3. 枚举班级序号范围（通常01-50）
4. 枚举专业代码（通常01-20）
5. 利用"用户不存在"/"密码错误"不同返回提示区分
6. 通过忘记密码功能验证学号是否存在
7. 通过注册接口验证学号是否已注册
```

## 六、PoC/Checklist

### 6.1 信息收集阶段检查清单

```
[ ] 搜索目标学校的学号编码规则（学校官网/学生手册）
[ ] 收集公开的学号样本（公示/获奖/竞赛名单）
[ ] 测试学号枚举接口（登录页/忘记密码/注册页）
[ ] 搜集学校统一身份认证系统类型（CAS/OAuth/LDAP）
[ ] 确认教务系统厂商（正方/强智/青果/金智）
```

### 6.3 漏洞利用优先级

```
第一优先级（入口点）：
  □ VPN弱口令     → 内网入口
  □ 邮件系统弱口令  → 敏感文件/钓鱼入口
  □ 统一认证弱口令  → 全系统通杀

第二优先级（拓展面）：
  □ 教务系统弱口令  → 学生数据/成绩/选课
  □ OA系统弱口令   → 审批流/组织架构
  □ CMS后台弱口令  → webshell/篡改

第三优先级（基础设施）：
  □ 摄像头弱口令   → 内网跳板
  □ 网络设备弱口令  → 网络流量/ACL
  □ 一卡通弱口令   → 物理门禁/消费数据
```
