**文章来源为：AI agent 自动采集整理**

**严重程度：** CRITICAL
**CVSS：** unknown
**CWE：** CWE-434
**影响版本：** SmarterMail Build 9406 and earlier

### 漏洞描述
该漏洞存在于SmarterMail Build 9406及以下版本。根本原因是服务器端对文件上传请求缺乏充分的验证。攻击者无需认证，可通过上传任意文件（如Webshell）至服务器任意位置，最终实现远程代码执行（RCE），导致服务器完全被控制。

### 攻击链
```
1. 信息收集：识别目标服务器上运行的SmarterMail服务及版本。
2. 版本确认：通过特定路径（如`/interface/root#/login`）和页面中的`ng-app`或`stProductVersion`变量判断版本号≤9406。
3. 漏洞利用准备：构造一个包含恶意代码的文件（如ASP/PHP webshell）。
4. 构造请求：向SmarterMail的文件上传接口发送HTTP请求，绕过客户端验证，将恶意文件上传至Web可访问的目录。
5. 执行利用：通过Web访问上传的恶意文件，触发代码执行。
6. 后渗透：在服务器上建立持久化访问，提升权限，横向移动。
```

### 利用条件
无需认证。攻击者需要能够访问SmarterMail服务的网络端口（通常为9998或80/443）。目标服务器运行SmarterMail Build 9406或更早版本。

### POC/利用
```bash
curl -X POST "https://[target]/Interface/Root/FileUpload.ashx" -F "file=@shell.aspx;filename=shell.aspx" --path-as-is
```

### FOFA 指纹
`app="SmarterMail" && version<="9406"`

### 修复建议
升级至SmarterMail Build 9407或更高版本。建议从SmarterTools官方渠道获取并安装最新的安全更新。

### 检测方法
1. 版本检测：访问目标登录页面，检查是否存在`ng-app="smartermail"`和`stProductVersion`变量，提取构建号并与9406比较。2. 漏洞验证：尝试向已知的文件上传接口发送携带无害测试文件的请求，观察是否返回成功响应。
