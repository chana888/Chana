### 漏洞描述
WordPress Core REST API 批处理端点 `/batch/v1` 存在路由混淆漏洞（CVE-2026-63030），与 `WP_Query` 的 `author__not_in` 参数 SQL 注入（CVE-2026-60137）链式组合，可实现未认证远程代码执行。

**攻击链路：**
1. `serve_batch_request_v1()` 构建两个并行数组 `$matches` 和 `$validation`，当子请求路径解析失败时，`$validation` 多一个元素但 `$matches` 不变，导致数组错位
2. 嵌套两次利用：第一次绕过方法白名单，第二次将 `author_exclude` 字符串注入 `WP_Query` 的 `author__not_in` 参数
3. `is_array()` 检查被绕过，原始值直接插入 `NOT IN (...)` SQL 子句
4. 结果：未认证布尔/时间盲注 SQL 注入
5. 通过 SQL 注入读取管理员密码哈希 → 离线破解 → 上传插件 webshell → RCE

**影响范围：** 500M+ WordPress 站点（Searchlight Cyber 估计），默认安装无插件即可利用。

### FOFA 指纹
`app="WordPress" && body="/wp-json/batch/v1"`

### 修复建议
1. **紧急升级**：WordPress 7.0.2 或 6.9.5 或 6.8.6
2. **临时缓解**：在 WAF/边缘设备阻止 `/wp-json/batch/v1` 和 `rest_route=/batch/v1`
3. **临时缓解**：通过 `rest_pre_dispatch` filter 要求批处理端点认证
4. WordPress.org 已强制自动更新
