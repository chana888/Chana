# 功能操作与动态接口发现（MCP Chrome Extension 0.0.19）

只处理本次授权账号、可见模块和允许的业务状态。先结合现有 JS/路由清单理解模块，逐模块实际点击，再把新 JS、路径、参数和真实请求回填；仅看首页或接口数量不能说明功能覆盖。

## 正常操作

- 用 `chrome_page_snapshot` 取得结构与 ref，用 `chrome_get_interactive_elements` 按文字/选择器定位真实控件。
- 菜单/页签：展开并点击，核对活跃项和业务内容变化。
- 查询/筛选：`chrome_fill_or_select` 填入正常值，`chrome_click_element` 提交正常查询，保留正文与字段位置。
- 列表：实际执行适用的分页、排序、下拉、级联、详情、弹窗、预览；长页只按当前工具支持的键盘/滚动行为操作，并核对位置变化。
- 附件/导出/上传：先读按钮含义与副作用；受控对象与权限不足则记录具体阻塞。不能为覆盖而盲点审批、支付、短信、删除或未知状态操作。
- iframe：内容在子 frame 时用带 frameId 的 CSS selector 或带 frame 的 ref 点击（2026-10-13 实测可用；坐标点击不支持 iframe 内元素）；frameId 按 tab 实测、跨标签不复用。快照缺子文档时记录限制，不得因外层选择器未命中就断言目标功能不存在。新标签/懒加载区块首读为空先等 3-5 秒重读再判定；层级导航可能纯客户端切换（URL 不变），以快照内容变化为准。

## 动作与抓包关联

1. 确认活跃 URL、账号/租户标签和前置状态；当前版本不是多账号隔离环境。
2. 开始 `chrome_network_debugger_start`，不要刷新真实页面或清除他人网络历史补包。
3. 执行一个正常动作，分别核对 UI 变化和网络请求，再停止捕获。一个动作可能对应多个业务包；UI 改变不能替代请求证据，请求出现也不能替代 UI 生效证据。
4. 保存实际请求 ID、URL、方法、字段、头、正文、响应及截断信息；不同 method/业务分发/DTO 结构分别记录。
5. 工具返回 success、图片大小变化或菜单 CSS 变化都不能单独证明业务动作成功。需有明确 UI 结果，且有真实业务请求或已证实的纯客户端/缓存来源。

## 覆盖台账

每项保留 action_id、context、module、page_url、action、precondition、ui_result、status、request_ids、evidence、new_js、gap、next_step。

- captured：正常动作生效且有可用业务请求证据。
- ui_only：已证实为纯客户端或缓存操作，保留判断依据。
- pending：尚未执行的可达动作。
- blocked：缺账号、对象状态、权限或无法执行的副作用。
- inconclusive：点击/抓包/归因失败；不能记为已排除。

请求摘要不足、头/正文缺失、抓包截断、解析失败如实留缺口。交接 `request-triage` 时同时给功能台账和实际原包/已捕获结果；捕获摘要不是完整 HAR，不在转换过程中造字段。D0/D1 门控通过后再派验证任务；共享浏览器的页面操作保持串行。

## 目标功能交互工具选择

**仅需要操作目标页面功能时使用本 MCP**：点击菜单/页签、填写表单、分页/排序/滚动、查看详情/预览、登录交接，或采集这些正常动作触发的请求。JS/源码、离线原包和证据分析、情报查询、路径/端口探测以及专项工具验证继续使用各自工具，不需要先调用浏览器状态；补正常功能请求或当前页面状态时再回到本流程。

ChanaAgent Harness 的工具前缀为 `mcp__chrome_mcp__*`；平台 Eino 入口的同一外部服务工具名形如 `vps-browser__chrome_click_element`。使用当前工具目录的对应名称和 schema，不混用两个入口的前缀。

具体流程见 `/opt/chana-vps-browser/workflow-agent.md`。
